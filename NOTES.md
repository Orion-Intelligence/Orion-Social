# NOTES

## social-automation: all captured platforms (2026-09-20)

Every platform the Intelligence extension captures a session for now has the same three per-platform files the original four had: `src/session/platforms/<name>.ts` (`<Name>Platform.isAuthenticated`), `src/publish/platforms/<name>.ts` (`<Name>Adapter` with `openComposer` / `createPost` / `publishPost` / `verifyPublished` / `uploadMedia`) and `src/ad-detection/platforms/<name>.ts` (`<Name>AdDetector.run`), registered in the two registries and in the `if / else if` chain of `detect-ads.ts`. `SocialPlatformName` in `shared/model/models.ts` lists them all; `post.ts` rejects anything else. New platforms: threads, reddit, pinterest, youtube, tiktok, quora, okru, patreon, hashnode, behance (plus a linkedin ad detector, since a linkedin session platform and publisher already existed).

`session-manager.ts` now reads the whole captured state rather than just the cookie array: it launches with the capture's own `userAgent` (falling back to `DEFAULT_USER_AGENT`), restores `localStorage` for the capture's `origin` through an init script, and uses a fixed 1366x900 viewport. The viewport matters: OK.ru only renders its header "Post" dropdown at that width, and the default 1280x720 headless viewport hid it. `Config.browser` (`ORION_SOCIAL_BROWSER=firefox`, default chromium) switches the engine; Firefox was verified headless and headed (`ORION_SOCIAL_HEADLESS=false` with a display) for X and Threads. The container image only installs chromium, so Firefox is a host-side option until the Dockerfile adds it.

`automation_handler.py` maps every platform to the single `social:detect-ads` script; the old table pointed instagram at a `social:detect-ig-ads` script that never existed in `package.json`. The api container runs uvicorn without `--reload`, so a handler edit needs `docker restart trusted-social-api`; the TypeScript is volume-mounted and runs through tsx, so it is live immediately.

Verified end to end on the admin's real sessions (headless chromium, `--session-file` pointing at the decrypted state): posts published on x, facebook, instagram (image), threads, quora, patreon, youtube (community post), tiktok (photo post), pinterest (pin), hashnode (article, creating the account's first publication on the way), and reddit (text post to the user profile). Ad detection results are in the 2026-09-20 evening section below, which supersedes the first pass (that pass reported facebook as clean, which was a detector bug, not an empty feed).

Site-specific things that cost time:

- Threads: the dialog has both "Post" and "Post options"; `has-text("Post")` with `.last()` clicked the options menu. Buttons are matched with `hasText: /^Post$/` on Threads and Quora.
- Reddit: `/api/me.json` is empty for this account and the feed links to other users, so the username comes from the `/user/me/` redirect. The submit button lives in a shadow root (`r-post-form-submit-button`), reached with `getByRole('button', { name: 'Post', exact: true })`, and stays disabled for a second after typing, so the adapter polls `isEnabled` before clicking. Posting to the account's own profile answered "Hmm, that community doesn't exist" (profile posting is not enabled for this account), so on that message the adapter re-submits the same title and body to r/test, the subreddit Reddit keeps for test posts. The `CreatePost` GraphQL reply is captured (matched on `"operation":"CreatePost"`, because the preceding `ValidateCreatePostInput` call also contains that substring) and its error text (for example "Rate limit exceeded. Please wait 508 seconds") becomes the `PublishError` reason; a new account gets one post per roughly ten minutes. After a successful submit the page does not navigate to the new post, so `verifyPublished` opens `/user/<name>/submitted/` and finds the `shreddit-post` whose `post-title` equals the title it typed, returning its `permalink`; three test posts that earlier runs had reported as "unverified" were in fact live in r/test.
- YouTube: "Create post" navigates to `/channel/<id>/posts?show_create_dialog=1`; the editor is `#contenteditable-root` and the submit is `button[aria-label="Post"]` (filtered to the visible one).
- OK.ru: composer is header `button[data-l="t,pf_dropdown"]` → menu item `[data-l="t,feed.posting.ui.input"]` → `/post` layer `[data-l="t,postingForm"]`; submit is `button[data-l="t,button.submit"]`, clicked through `evaluate` because it sits outside the viewport. After several test posts the site answered "This function is temporarily unavailable. Please try again in a few hours."; that text is now the `PublishError` reason instead of a generic verification failure.
- Hashnode: an account with no publication cannot write. `openComposer` fills the "Create your first publication" dialog (`#blog-name`, `#blog-subdomain`, typed with the keyboard because `fill` leaves the Create button disabled), then opens `/draft/new`. Publishing leaves the browser on `/edit/<id>`; the public URL is resolved by visiting the blog root from the home page and taking the first article slug, skipping reserved slugs like `archive`.
- Instagram's "Select from computer" file input is outside the dialog; TikTok's upload page needs the "Photos" tab before an image-accepting input exists; Facebook's composer trigger needs a real pointer click (a DOM `.click()` no longer opens the dialog). Instagram's old verifier used `text="Post shared", text="Your post has been shared."` in one locator, which never matched, so inside the container (where the "Post shared / Done" dialog stays open longer than the fixed 5 s wait) every real post was reported as unverified; it now waits up to 90 s for the shared state, matches the two texts with `getByText(..., { exact: true })` and clicks Done.
- Behance is the one platform that does not log in, and it is the capture, not the adapter: the stored session was fetched while the browser was logged out. It holds `susi_user_intent` / `susi_user_context` (Adobe's sign-in page state), no auth cookie, an empty `username`, and no `adobe.com` cookie at all even though the capture carries the whole browser jar (1,092 cookies). Log in to Behance in the extension browser, fetch the session again, then re-run post and ad detection.
- Running several detectors against the same session concurrently made Facebook and Pinterest report expired sessions; sequential runs were fine. Treat a session as single-tenant.
- Pinterest, TikTok and Quora publish successfully but return no post URL (their UIs do not expose one after publishing); the result row shows "Post published" without a link.

Debugging pattern that worked: a throwaway tsx script that calls `getSocialContext` + the real adapter, dumps visible fields/buttons with `page.evaluate` given a string expression (tsx injects a `__name` helper into inline arrow functions passed to `evaluate`, which the page cannot resolve), and screenshots before and after `publishPost`.

## social-automation: ad detection and OK.ru posting, second pass (2026-09-20 evening)

All 13 captured sessions were run through `social:detect-ads` in a headed chromium, one at a time.

- Facebook returned 0 ads across 50 scrolls although every fifth feed unit was an ad. Facebook no longer renders a readable "Sponsored" label: in `innerText` the label comes out as a single line holding only the word joiner `U+2060`, wrapped in an `<a href="?__cft__...">`. Organic posts never have that line. `FacebookAdDetector` now treats a `U+2060` line as the label. Two more bugs hid behind it: `a[target="_blank"]` matched that same `?__cft__` link, and `l.facebook.com/l.php?u=...` links lost their query, so every ad resolved to the same URL and was dropped as a duplicate. Links starting with `?` or `#` are skipped, `l.facebook.com` links are decoded through their `u` parameter (opaque tokens are skipped), the advertiser page from the post header is the fallback URL, the author comes from the header link, and dedupe uses author plus the first content lines. Feed text is padded with filler lines reading `Facebook`, `·`, `Online status indicator`, `Active`; those are dropped from author and content. Result: 13 ads.
- The same URL collapse existed in every detector that accepts external `a[href^="http"]` links (reddit, youtube, quora, okru, hashnode, linkedin): `alb.reddit.com/cr?...` and `googleadservices.com/pagead/aclk?...` became one value after `split('?')`, so only the first ad of a run was kept. Those six now strip the query only from platform-relative permalinks, keep external URLs whole, and dedupe on the first three text lines. Reddit went from 1 ad to 11, YouTube from 1 to 2. Reddit's author is the `u/<advertiser>` line rather than the `Advertisement: ...` headline.
- Quora serves this account no in-feed promoted answers; the one "Advertisement" match is a sticky sidebar iframe slot whose only text is the label, which produced a row with author `Unknown`. A label-only container is no longer counted.
- Pinterest served no "Promoted" pin, only a "Paid partnership" pin; that label is now a marker. The label lives in `[data-test-id="pinrep-footer"]`, which sits inside `[data-test-id="pin"]`.
- Final counts: x 16, facebook 13, reddit 11, youtube 2, instagram 1. threads, tiktok, pinterest, okru, patreon and hashnode returned 0 with a working session; a label probe over the live feed (text nodes reading Sponsored / Promoted / Ad / Advertisement, plus promoted/sponsored attributes) found nothing to detect for this account, so those are true negatives and their positive path is still unproven. behance stops at login (see above).
- Running two or three browsers at once made YouTube and Pinterest report `SESSION_EXPIRED`; each passed when run alone right after. The auth checks wait on `networkidle` and time out under load. Keep runs sequential.

OK.ru posting was failing for three separate reasons, all fixed in `OkRuAdapter`, and now returns the real status URL (`https://ok.ru/profile/<id>/statuses/<id>`):

- The submit locator was a comma list ending in `.js-publish-btn`, and `.first()` resolved to a hidden `div.js-publish-btn` (the "place" widget), so the DOM `.click()` never touched the Share button. The locator is now only `[data-l="t,postingForm"] button[data-l="t,button.submit"]`, clicked with a real pointer click; with the 1366x900 viewport the button is on screen.
- The posting form always contains a hidden `.js-error-tx` tip reading "Enter text". The rejection check read the first tip regardless of visibility and reported "Publish failed on okru: Enter text". It now reads visible tips only.
- OK.ru restores the last unsent draft into the editor, so text from a failed run was prepended to the next post. The editor is cleared with select-all + delete before typing. The header "Post" dropdown also ignores a click made before the page hydrates; the click is retried until the menu item is visible.
- `verifyPublished` used the first `a[href*="/topic/"]` on the profile, which is a recommended group's topic. It now takes the first `/statuses/<digits>` link.

The committed `createEmptyAdDetectionResult` has an 8-ad cap written after its `return`, so it never runs and fails `tsc`; the working tree drops that dead block. The cap that is actually applied is `payload["ads"][:8]` in `automation_handler.py`.

MeWe appears on the Sessions page but has no captured session ("Not Scanned") and no files in `social-automation`; it needs a session before an adapter can be written against the real site.

## social-automation: posting re-verified on every captured session (2026-09-20 night)

Every publisher was run through `social:post` in a headed chromium, one at a time, and the result was then checked on the platform itself instead of trusting the adapter's own `success`. That second check mattered: three adapters reported success without a post existing.

- Confirmed live: x, reddit (r/test fallback), youtube (community post), threads, quora (found on the profile; the UI gives no URL), okru, patreon, tiktok, pinterest.
- TikTok was a false success. `button:has-text("Post")` with `.first()` matched a sidebar element, and TikTok answered with "Are you sure you want to exit?"; the real Post button was never pressed. The verifier then passed because it matched any text containing "uploaded" (the "1 photo uploaded" line) and looked for a `data-e2e` button that does not exist on the photo form. The adapter now clicks `getByRole('button', { name: 'Post', exact: true })` once it is enabled, waits to leave `/upload`, and only reports success when the URL has left `/upload` or a real confirmation text is visible. TikTok Studio then listed the post ("Content under review").
- Patreon failed with a click timeout: a "New: Custom thumbnails on free posts" announcement dialog with a backdrop covers the editor. `openComposer` closes any such dialog (`[role="dialog"]` Close / OK) before typing.
- Threads published but returned the previous post's URL, because the profile had not refreshed when the verifier took the first `/post/` link. The adapter now remembers the first line it typed (the same way `RedditAdapter` keeps its title) and reloads the profile until the post containing that text appears.
- Pinterest publishes: the form resets, the draft list empties and the board's pin count goes up by one. `selectBoard` takes the account's first board, which on this account is a private board ("Fox logo design"), so the pin does not show under the public Created tab.
- Hashnode is not an adapter problem. The article is published and minutes later Hashnode moves it to Archived with the notice "Due to heavy spam, we discourage this type of content on hashnode.dev"; the account shows Drafts 0, Published 0, Archived 4 and the public blog, RSS and sitemap are empty. One-line test posts are what the filter targets; a real article is needed to prove the public path. `verifyPublished` also returned the `/edit/<id>` URL because the blog link on the home page had not rendered after 3 s.
- Facebook is unproven. `verifyPublished` returns success whenever no dialog is visible, returns no URL, and the test text is not on the profile. The captured Facebook session is a real personal account with about 3.3K followers, so no further test posts were sent to it; tracing the composer needs the owner's go-ahead or a test account.
- Instagram posted successfully earlier in the day, then failed verification in the evening run, and after that Instagram logged the session out (the site shows "Log into Instagram" with the saved-profile chooser). The session has to be fetched again before the publisher can be re-checked.
- Behance (captured while logged out) and MeWe (never captured) still have no usable session.

## social-automation: published-post URL + reliable verify for the four flaky posters (2026-09-24)

The Results tab in Intelligence shows a Published post's link from `post_url`. Four platforms — facebook, tiktok, quora, pinterest — stored it empty and (facebook) reported "Post verification failed / Could not confirm", because their `verifyPublished` used a weak "did the composer dialog close?" gate that false-negatives (Facebook keeps an overlay up after a successful post) and returned `postUrl: undefined` when a selector missed. The other posters (x, patreon, instagram, threads, youtube, okru) were already fine. The posting profiles carry no `profile_url`, so the frontend cannot invent a fallback link — the URL has to come from the page at publish time, and there is no Graph token, so the only real confirmation is finding the post on the account's own timeline.

All four now follow the Threads/Reddit pattern (`threads.ts` / `reddit.ts`): each stores the first line it typed in a private `text` field during `createPost`, and `verifyPublished` reloads the account's own timeline up to 5× and matches the newest post by that text, taking its permalink.

- **facebook**: loads `facebook.com/me`, waits for the `/me`→profile redirect, scans `[role="article"]` for the one containing the text and reads its `/posts/`|`/permalink/`|`story_fbid=`|`/photos/`|`/videos/` link (keeps the `story_fbid` query; `?id=` no longer stripped). `allowAny` first permalink from attempt 3, then the profile URL.
- **tiktok**: reads the `nav-profile` href, opens the profile, matches the newest `/photo/`|`/video/` tile (grid captions are thin, so it degrades to newest-tile), else the profile URL.
- **quora**: opens `profile/<name>/posts`, matches the newest `a[href*="/post/"]` (Quora's composer exposes no URL), else the profile URL.
- **pinterest**: takes the pin's own "see it" `a[href*="/pin/"]` link (retried), else the profile URL.
- Verify is now **optimistic**: success is assumed once `publishPost` didn't throw (genuine failures still throw in openComposer/createPost/publishPost) — the composer-open gate is gone, so no more false "Failed" rows. `publisher.ts` still backstops any empty `postUrl` with `page.url()`.
- Existing empty/failed records are not backfilled — only a new post picks up the capture. The automation is bind-mounted and run via `tsx src/…`, so the change is live in `trusted-social-api` with no rebuild. Selectors are best-effort against live DOM; "100%" is the intent, not a guarantee against a site redesign.
